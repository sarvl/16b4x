[OVERVIEW]
	This manual describes the interface and internal behavior of video controller

[EXTERNAL]
	[INTERFACE]
		[SOFWTARE]
			The device should use interface from VRAM screen [IO:PREDEFINED:VRAM_SCREEN] 
			The hardware interface should be adjusted by Catalyst

		[HARDWARE]
			Hardware interface is composed out of:
				- input  address      (16bit)
				- input  data         ( 8bit)
				- input  write enable ( 1bit)
				- output ready        ( 1bit)
				
			Data is read ONLY when ready is 0 and write enable is 1, otherwise there is NO change in state

			Upper 8 bits of address determine vertical   position, they must always be multiple of 8
			Lower 8 bits of address determine horizontal position

			Position is counted from top left corner of the screen

	[INTERRUPTS]
		The video controller never issues any interrupts
		
[INTERNAL]
	[HIGH_LEVEL]
		High level driver is implemented as VRAM
		Whenever low level driver is ready, it forwards data there
		Due to clocked behavior of change state, it only sends data when driver turns ready
		Otherwise it accepts input to the VRAM

		It keeps pointers to row and column that are used to retrieve appropriate data
		They go from all ones to all zeros due to how screen ordering works

	[LOW_LEVEL]
		Low level driver is implemented as state machine which (in order)
		1. initializes screen via reset pin
		2. sends commands with spi-like interface
		3. waits for data
		4. sends 8 bits to the screen, goes back to 3

		to reduce number of states in looping, counters like bit_ind and cmd_index are used 

		the delays might be able to get shorter, they were set somewhat by trial and failure
